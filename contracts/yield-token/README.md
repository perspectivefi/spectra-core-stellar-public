# yield-token

SEP-41 token representing a user's claim on yield generated by the paired `principal-token`. Mirrors Solidity's `YieldToken.sol`. See spec-03 for the full spec; this README documents the Soroban-specific choices and how they differ from the Solidity reference.

## Architecture

- **Base token surface** — reuses OpenZeppelin `stellar_tokens::fungible::Base` for `balance`, `allowance`, `approve`, `transfer`, `transfer_from`, `total_supply`, `decimals`, `name`, `symbol`. YT overrides only what maturity + yield semantics require (see below).
- **Pause mechanism** — implements OZ `Pausable` via `stellar_contract_utils::pausable`. State-changing functions carry `#[when_not_paused]`.
- **Cross-contract calls to PT** — routed through the `PrincipalToken` trait declared in `principal-token/src/interface.rs` (single canonical interface; compile-time enforced by PT's own `impl PrincipalToken for PrincipalTokenContract`).

## Solidity-to-Soroban differences

| Solidity | Soroban | Why |
|---|---|---|
| `ERC20PermitUpgradeable` | SEP-41 via OZ `stellar_tokens::fungible::Base` | Drop ERC2612 permit — Soroban auth replaces it. Reuse OZ rather than rolling a custom SEP-41. |
| `IERC20Metadata(pt).decimals()` live on every read | Cached on YT via `Base::set_metadata(env, pt.decimals(), name, symbol)` at `initialize` | PT's metadata is immutable (no admin setters). Caching saves ~5k–10k CPU instructions per read vs. a cross-contract call. See issue #31. |
| `IPrincipalToken(pt).paused()` live on every state-changing call | Mirrored locally via OZ pausable + `#[when_not_paused]`. PT pushes changes via `yt.pause()` / `yt.unpause()`. | Same cost argument. No intra-tx drift risk (Soroban allows one Soroban op per tx — push runs atomically with PT's own state change). |
| `_update` hook with `whenPTNotPaused` modifier | `#[when_not_paused]` on each state-changing fn | Soroban has no hook pattern; explicit per-function guard. |
| `super.balanceOf` vs overridden `balanceOf` | `actual_balance_of` vs `balance` | Explicit separation — no `super` in Rust. |
| `_disableInitializers()` in constructor | `is_initialized` flag check in `initialize` | Different init idiom. |
| `pt.before_yt_transfer(from, to)` — PT calls back into YT for balances | `pt.before_yt_transfer(from, to, from_balance, to_balance)` — YT passes pre-transfer balances | Soroban's host-level reentrancy guard blocks PT → YT back-calls while YT is on the stack. See spec-04 §17.1. |

## Caching policy — what's local vs. live

| Value | Storage | Mutable in Solidity? | Push-on-change? |
|---|---|---|---|
| `decimals`, `name`, `symbol` | Cached on YT (OZ `Base`) | ❌ immutable | Not needed — reintroduce PT-only setters if that ever changes |
| `paused` | Mirrored on YT (OZ `pausable`) | ✅ via `pt.pause`/`unpause` | Yes — PT pushes via `yt.pause()` / `yt.unpause()` |
| `maturity` | Cached on YT (`DataKey::Maturity`) at `initialize` | ❌ immutable | Not needed — reintroduce a PT-pushed setter if that ever changes |

PT pushes `maturity` into `yt.initialize(..., maturity, pt)` the same way it pushes `decimals`. The Soroban host reentrancy guard blocks YT → PT calls while PT is on the stack at init, so the value must be pushed in. Caching also decouples YT liveness from PT's instance TTL — a YT read no longer requires PT to be alive in storage.

## PT responsibility

When PT calls these, PT **must** also call the corresponding YT function in the same invocation:

| PT state change | Required YT call |
|---|---|
| `pt.pause(caller)` | `yt.pause(pt_addr)` |
| `pt.unpause(caller)` | `yt.unpause(pt_addr)` |

`yt.pause` / `yt.unpause` carry an `Address` arg only to match OZ's `Pausable` trait signature. YT ignores that arg and enforces the PT-only policy directly via `storage::get_pt(env).require_auth()`. Auditors flagging the unused parameter (`YT.Tamper.2`): dropping it would break trait conformance.

If PT ever gains mutable metadata, add corresponding `yt.set_decimals` / `yt.set_name` / `yt.set_symbol` setters with the same push pattern.

## Auth invariant on `burn_without_yield_update`

The self-path (`owner == spender`) deliberately skips `owner.require_auth()`. The gate is `pt.require_auth()` only. The invariant — *PT only reaches this branch with owner-side consent already established* — is convention, not code.

Concretely:
- Self-redeem / self-withdraw: PT's outer entrypoint takes `caller.require_auth()` against `owner` before issuing the YT burn.
- Behalf-of via approval: PT consumes a PT-side allowance (`Base::burn_from` on PT shares) before the YT burn.

Future PT changes that add YT-burning code paths MUST preserve this invariant or rework the YT side to require `owner.require_auth()` (which would break the current Router-driven flows). Tracked: audit-pass1 `YT.Tamper.3`.

## Upgradeability

`upgrade(new_wasm_hash)` is gated by `pt.require_auth()` and calls Soroban's native `env.deployer().update_current_contract_wasm(...)`. There is no proxy or beacon — each YT instance upgrades itself in place. Authorization policy lives on PT (whose admin holds `UPGRADE_ROLE`); PT decides when to roll YTs forward and authorizes the call. Existing YT instances are not auto-upgraded when `registry.yt_wasm_hash` changes; each must be triggered individually.

`upgrade` is intentionally **not** wrapped in `#[when_not_paused]`. A paused YT must remain upgradeable so PT's admin can patch out the bug that caused the pause. Audit ref: `YT.Tamper.4`.

## TTL management

YT has no persistent per-user state beyond what OZ `Base` owns (balances, allowances). Both OZ `Base` and OZ `pausable` manage their own TTL. The only YT-owned state is `DataKey::Pt` in instance storage, extended on every state-changing operation via `storage::extend_instance_ttl`.

- **Instance storage** (`Pt`, OZ metadata, OZ pause flag): extend to `max_ttl()` on every mutating call.
- **OZ `Base` persistent entries** (balances, allowances): managed by `Base`; TTL extended by OZ on each write/read.

## Errors

YT-specific errors are minimal — OZ owns most of them:

```rust
#[contracterror]
pub enum YieldTokenError {
    AlreadyInitialized = 1,
}
```

Auth failures on `pause` / `unpause` / `mint` / `burn_without_yield_update` / `upgrade` come from `pt.require_auth()` and surface as Soroban Host.Auth errors, not a YT-level variant. Pause-guard failures come from OZ pausable (via `#[when_not_paused]`).

Balance / allowance failures use `stellar_tokens::fungible::FungibleTokenError::{InsufficientBalance, InsufficientAllowance, LessThanZero, InvalidLiveUntilLedger}`. Don't duplicate. `allowance` panics with `InsufficientBalance` post-expiry (mirrors `transfer`/`burn`).

## Testing

Run `cargo test -p yield-token`. Tests use a `MockPrincipalToken` stub registered alongside YT; the stub implements the `PrincipalToken` trait with far-future maturity and no-op yield callbacks, so pre-expiry tests don't need to simulate real PT behavior.
